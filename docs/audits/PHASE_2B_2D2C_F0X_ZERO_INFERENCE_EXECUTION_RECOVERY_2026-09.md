## 3. Defect 1 — relative freeze path reaches the scratch-cwd child

**Root cause, verified against committed code (`74ee8a4`):**

- `f0w/slotExecutionPlan.ts` `buildSlotExecutionPlanTemplate` returns `freezePath: identity.historicalFreezePath`, the RELATIVE `F0I_FREEZE_PATH`/`F0O_FREEZE_PATH` constant.
- `f0x/studyExecutor.ts` passed `freezePath: template.freezePath` straight into `runExperiment`, which copies it into the child manifest unchanged.
- `processIsolatedBatch.ts` forks every child with `cwd: scratchDir`; `childMain.ts` step 2 does `deps.readFile(manifest.freezePath)` → ENOENT → `preflightStop('CORPUS_CONFIG_OR_HASH_DRIFT', …, { stage: 'freeze' })`.
- Precedent: `f0o/cliF0O.ts:548` resolves `join(RUNNER_REPO_ROOT, F0O_FREEZE_PATH)` itself; every earlier test also passed `join(ROOT, …)`. F0X was the first caller to pass the template value through, and its physical test asserted only `CORPUS_CONFIG_OR_HASH_DRIFT` — which both the `freeze` and the intended `variantRoot` stage produce — so it masked the defect.

**Physical proof:** through the real Tier-2 harness (real fork, real scratch cwd, real `childEntry.mjs`), passing the pre-fix relative path reproduces the preserved `child-preflight.json` **byte-for-byte** for both V4 (file `d941b842…`, record `547e3bd5…`) and V5 (file `4b344e88…`, record `d86be5c0…`).

**Fix (smallest correct boundary):** new `f0x/childFreezePath.ts` `resolveChildFreezePath` resolves the template's relative path against the runner repo root. It requires the root to be absolute and the template to name exactly its variant's frozen relative path. It also requires the bytes at the absolute path to hash to both the plan's `freezeConfigRawSha256` and the frozen F0I/F0O hash. Otherwise it throws `ChildFreezePathError`, with no fallback. `studyExecutor.ts` resolves this for all ten slots **before** the all-ten preflight (a failure writes nothing, consumes nothing and dispatches nothing). It passes the absolute path through the exported `buildSlotExperimentInput`. `cliF0X.ts` supplies `runnerRepoRoot: RUNNER_REPO_ROOT`. The relative path remains the identity. The F0I/F0O freeze bytes, `childMain.ts`, `coordinator.ts`, `childEntry.mjs` and `processIsolatedBatch.ts` are byte-unchanged.

## 4. Defect 2 — pre-inference STOPPED slots advanced as Class C

**Root cause, verified against committed code (`74ee8a4`):**

- `studyExecutor.ts` step 3d: *"Whatever the outcome, `runExperiment` always wrote a terminal record … — the slot is durably closed, Class C, and the loop advances"*. It wrote `SLOT_COMPLETED_CLASS_C` for any returned experiment, STOPPED included.
- `f0w/sequencing.ts` `INFERENCE_CAPABLE_ARTIFACT_FILE_NAMES` included `child-manifest.json`, `child-preflight.json`, `child-failure.json`, `final-record.json`, `stop-decision.json`, `tier2-outcome.json` and `experiment-completion.json`. Any of them made a slot `SEMANTIC_EXECUTION_OBSERVED`. So slot N+1's sequencing gate also read slot N as Class C, durably closed, and granted it. Both layers agreed on the wrong answer, and the study spent all ten candidates in about 5 seconds.
- `childMain.ts` writes `CHILD_PREFLIGHT {ok:false, providerConstructed:false}` only on its `preflightStop` path, which returns before step 7 (`providerFactory.create`). Provider outcome, raw checkpoint, validation, Tier-1 diagnostics and child result are written only after `provider.classify` returns. Those two facts are what the correction keys on.

**Fix:**

- `sequencing.ts`: Class C now requires a real semantic-execution marker (`SEMANTIC_EXECUTION_MARKER_FILE_NAMES`: provider outcome, raw output checkpoint, validation result, Tier-1 diagnostics, child result, any repair artifact). Child manifest, preflight, final record, stop decision and Tier-2 outcome are admitted only inside an attempt directory whose `child-preflight.json` re-verifies its own `recordSha256`, has `artifactKind: CHILD_PREFLIGHT`, `ok: false` **and** `providerConstructed: false` → Class B. Everything else is `AMBIGUOUS` and blocks: a manifest without a preflight, a preflight without a manifest, a preflight with `ok: true` and no marker, `providerConstructed` not false, a tampered or unreadable preflight, `child-failure.json`, or any unexplained file. The classifier reads file content **only** for `child-preflight.json` (new `readFile` probe).
- `studyExecutor.ts`: after `runExperiment` returns, the slot's own root is re-classified fresh. Only Class C **and** durably closed writes `SLOT_COMPLETED_CLASS_C` and advances. Class B writes `SLOT_PAUSED_CLASS_B`. Ambiguous, or Class C not closed, writes `SLOT_AMBIGUOUS`. Either way the terminal is `PAUSED`, returned as `pauseKind: 'POST_EXECUTION_EVIDENCE'` with the classification and experiment. Gate refusals are now `pauseKind: 'GATE_REFUSAL'`.

**Deliberate fail-closed consequence (for owner awareness):** if slot 1's only child passes preflight (`ok: true`) and is then killed or crashes before writing any marker, the slot is `AMBIGUOUS` and the study pauses. A provider request can be neither confirmed nor excluded there. Once any evaluation in a slot has left a marker, later evaluation failures in that slot remain Class C.
